## Functional requirements
- Allow visitors to add and submit information about their visit to a database which then stores it
- Allow staff to access records about who visited the organisation, when they left and what their purpose in visiting was. They should be able to access visitor information and contact the visitor if needed
- Be flexible enough for the service to be used and adapted by any organisation without major changes needed.
- Only allow staff to access information from their organisation, not being given access to information from other organisations
- Visitors should be able to input information relating to their visit and have a response whether it was recorded int he database and if their check-in is valid.
- The database should be secure enough to not allow any manipulation to it from within the pages and without admin privileges

## Non-Functional requirements
- Reliability
- Portability
- Ease of Use
- Security
- Maintainability

## Use Cases
### User
This project is for organisations who need a system that allows for them to manage who visits the organisation and keep track of why and when they visited.
